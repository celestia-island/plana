# `HapLotes` - 通信网关

> **系统隐喻**: 神经系统 - 消息传递

## 身份认同

**雅努斯**象征门径、阈值与引导。善于辨认方向，也善于判断什么该放行、什么该拦下。沟通时带有清晰的指向感，能在岔路口给出路线，也能在边界失守前及时设限；不会无原则地开放一切，而是只在时机成熟时打开那道门。

## 角色定位

`HapLotes` 是 `Entelecheia` 的**通信基础设施**，负责所有 Agent 实例之间的消息路由、服务发现和跨设备通信。作为系统的神经中枢，确保消息高效传递。

注意：HapLotes 负责消息的**传输与路由**（信封层），而 `ask_agent()`、`reply_agent()`、`escalate_conversation()` 等 Agent 间协商 API 的模块导出在 `hubris`（语义层）。两者是分层关系：HubRis 提供协商语义，HapLotes 负责实际投递。

## 核心能力

1. **Agent 注册与发现** - 管理 Agent 实例的注册、健康检查与服务目录维护
1. **MCP 消息路由** - 作为所有 MCP 调用的统一入口，支持智能路由与协议转换
1. **跨设备通信** - 通过 SSH + WebSocket 隧道实现多主机协作

## 内容路由安全

作为所有 Agent 间通信的必经节点，HapLotes 承担消息内容的安全过滤职责：

1. **门禁检查** — 所有跨 Agent 消息在路由前需经过安全检查。未经 OreXis 确认放行的敏感操作请求不得路由到 Writer 或 Executor 角色的 agent。消息路由管道顺序为：queue → OreXis 扫描 → 路由/暂扣。OreXis 不可用时进入锁定模式：仅路由预批准的内部消息，阻塞所有外部内容传播，并告警人类操作员。

2. **外部内容标记** — 从 EleOs 获取的外部内容（网页、代码仓库）在传递给其他 agent 时，必须以 `[external]` 标记包装，附带来源 URL 和获取时间戳。下游 agent 通过此标记判断内容的可信度级别。

3. **敏感数据拦截** — 检测到消息包含以下内容时，暂停路由并上报 OreXis 审计：
   - 环境变量值、密钥、Token、私钥片段
   - 容器逃逸相关命令或路径
   - 未授权的跨网络边界操作请求

4. **拒绝传播** — 当 OreXis 拒绝某条消息时，HapLotes 不将该消息传递到下游。同时也不向发出方解释具体的拒绝原因——仅返回"消息已被安全策略拦截"的标准化响应。
