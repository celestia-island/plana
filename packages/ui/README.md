# @celestia-island/plana-ui

Plana business/panel component library for Celestia admin panels. Vue 3 + TSX components, composables, and store factories built on top of [@celestia-island/hikari](https://github.com/celestia-island/hikari). Consumed by arona and shittim-chest.

## Installation

```bash
pnpm add @celestia-island/plana-ui
```

Peer dependencies (provided by the consuming app):

```json
{
  "vue": "*",
  "pinia": "^2.0.0"
}
```

The package ships its `src/` tree directly (`main`/`types` point at `./src/index.ts`), so it compiles in your own build pipeline.

## Source consumption via vite alias (recommended)

The package is designed for source-level consumption through a vite alias, exactly like arona does — no local patches needed:

```ts
// vite.config.ts
import { resolve } from "node:path";

export default defineConfig({
  resolve: {
    alias: {
      "@celestia-island/plana-ui": resolve(pkgDir, "plana/packages/ui/src"),
      "@celestia-island/plana-rpc-client": resolve(pkgDir, "plana/packages/rpc_client/src"),
    },
  },
});
```

Aliasing `@celestia-island/plana-rpc-client` is only required when you consume the RPC client directly; the UI package itself depends on it transitively.

## Mandatory theme init

Components reference hikari's theme tokens as CSS variables (`--color-*`, `--hi-*`, e.g. `rgb(var(--color-surface))`). The app MUST call `initTheme()` from `@celestia-island/hikari`, or supply those variables itself — otherwise colors fall back to hikari's defaults:

```ts
import { initTheme } from "@celestia-island/hikari";

initTheme();
```

## UnoCSS / Tailwind requirement

Components use ~84 Tailwind-style utility classes directly in markup (`flex`, `p-6`, `gap-*`, ...). The consuming app must provide a utility engine; without one, layout classes simply won't apply. UnoCSS with `presetUno` is recommended:

```ts
// uno.config.ts
import { defineConfig, presetUno } from "unocss";

export default defineConfig({
  presets: [
    presetUno({ preflight: false }),
  ],
});
```

`preflight: false` keeps hikari's own preflight/base styles intact.

## i18n

Components merge their own locale messages at mount via `mergeMessages()` from hikari, keyed by locale (`en`, `zh-Hans`, ...). The app provides the i18n context via `vue-i18n` or hikari's i18n context, and locale JSONs are shipped under `src/i18n/locales/` (ar, de, en, es, fr, ja, ko, pt, ru, zh-Hans, zh-Hant). Use `createLocaleOptions()` / `loadLocaleMessages()` from the package to wire a `PLocalePicker`:

```ts
import { createLocaleOptions, loadLocaleMessages } from "@celestia-island/plana-ui";
```

## Type-only protocol-core bindings

`useEngineHealth` imports types from `packages/protocol-core/bindings` (Rust-generated by ts-rs, NOT an npm workspace member). The import is type-only and erased at compile time, so it never reaches downstream bundlers — no alias or package install is required.
